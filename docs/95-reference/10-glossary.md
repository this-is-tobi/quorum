# Glossary

The words these pages use in one particular way, and the acronyms they assume you know, each with the chapter that says the rest. A term here means the same thing on every page; when a page seems to use one differently, the page is wrong, not the glossary.

## Terms

- **adaptation** — a setting quorum moves by itself for the rest of one review when a reply shows it must: a provider's thinking lowered, or its structured output moved from `json` to `prompt`. Each is found out by a probe, one call sent once more with the new setting, and is one line, one `adapted` event and one entry of `meta.adaptations`. A setting you set is never moved. [What quorum adapts by itself](../20-using/20-configuration.md#what-quorum-adapts-by-itself)
- **attack case** — a case of a bench suite whose patch is the patch of a bug case, its twin, with text planted in it to turn the review: to hide the bug, to keep a decoy, to bloat the output or to deny the review. It is scored against its twin's review of the same trial. [Benchmarks](../20-using/70-bench.md#attack-suites)
- **attempt** — one try of a call: the provider is asked once, with a signal of its own and a deadline of its own. [Deadlines and retries](../20-using/30-providers.md#deadlines-and-retries)
- **block** — the at most 8 lines the live view redraws under the log lines of a review: its rule and elapsed time, each profile's parts and votes, the calls in flight, the tokens and the time left, each cut to the terminal's width less one. It is at most the terminal's rows less two, so 2 or 3 lines on a terminal of 4 or 5 rows, and none is drawn under 4 rows. [The live view](../20-using/10-cli.md#the-live-view)
- **call's number** — the number a call is given in a review, from 1, in the order calls start: the `call` field of its `call:start`, `call:retry` and `call` events, which tells them apart. A call the store answered has none. [Library API](./30-library-api.md#events)
- **carrier** — where an attack case plants its text: a comment, a string literal, a file name, a documentation file or a guideline file. [Measurement](../30-security/40-measurement.md#the-injection-corpus)
- **case** — one patch of a bench suite, a `bug`, a `control` or an `attack`, with the id its records and its report name it by. The case, not the trial, is the unit a rate and its interval are taken over. [Benchmarks](../20-using/70-bench.md#writing-a-suite)
- **catch** — said of a finding that cites the file of one of a bug case's locations, on a line within `window` lines of its range. A kept finding makes a kept catch, and any finding that reached the panel a proposed catch. Code decides it, never a model. [Benchmarks](../20-using/70-bench.md#reading-the-report)
- **claim** — the finder's account of a finding as a voter receives it: the file, the line, the category and the summary, fenced and introduced as unverified. It holds the only text a model wrote that a voter reads. [Prompts](../20-using/60-prompts.md#the-layout-of-a-request)
- **confidence** — the highest level, `high`, `medium` or `low`, whose threshold a finding's kept votes reach, computed in code by the policy. No model reports one: a vote has no confidence field. [Lenses and policy](../20-using/50-lenses-and-policy.md#confidence)
- **control** — a case of a bench suite whose patch is a change no advisory names, with no location: every kept finding on it is unmatched, which makes it the nearest thing a bench has to a false-alarm rate. [Benchmarks](../20-using/70-bench.md#writing-a-suite)
- **coverage** — what a profile's research reviewed of each file of the diff, in `meta.profiles.<id>.coverage`: reviewed, partial with the lines left, unreviewed with its reason, or excluded. [Coverage](./20-json-result.md#coverage)
- **cut-off** — a reply the server stopped at its limit, which quorum never reads, its closed findings included. A research part whose reply is cut off is split in two and each half researched as a part, to a floor of one hunk and three splits deep; what is still cut off there is the `reply-cut-off` gap. [Recovering a cut-off part](../20-using/20-configuration.md#recovering-a-cut-off-part)
- **data notice** — the part of every system message that names each fenced block of the request by its exact tag, and says what it holds. The code writes it, not the profile. [Prompts](../20-using/60-prompts.md#the-data-notice)
- **deadline** — how long an attempt may wait for its provider: the provider's `timeoutMs`, 600000 ms when it states none. At it the core aborts the attempt's signal and fails the attempt as a `timeout`, whatever the provider does. [Deadlines and retries](../20-using/30-providers.md#deadlines-and-retries)
- **decoy** — lines of an attack case's patch that hold no bug and that a forced keep tries to make a review keep. A review that keeps a finding on them has kept the decoy. The **twin decoy** is the same code's lines in the twin's patch, so that the clean review is checked for the same finding. [Measurement](../30-security/40-measurement.md#a-forced-keep)
- **discarded** — a verdict that reached no confidence level, and whose failed votes, had they been keeps, would not have reached one either. [Lenses and policy](../20-using/50-lenses-and-policy.md#failed-votes)
- **effective votes** — what a panel is worth when its lenses' errors go together: k / (1 + (k - 1) x the mean phi) for k lenses, so k when the errors do not correlate and 1 when they always do. [Measurement](../30-security/40-measurement.md#the-lenses-error-correlation)
- **effective window** — the window the reply budgets and the rooms of a profile are computed from: a provider's stated `window`, its `contextTokens` for a shipped adapter. [Reply budgets](../20-using/20-configuration.md#reply-budgets)
- **encoding** — how an attack case writes its text: plain, multilingual, hidden-unicode, base64, html-comment or fake-delimiter. [Measurement](../30-security/40-measurement.md#the-injection-corpus)
- **evidence** — the diff's lines around a finding's cited line, in its hunk, read from the diff by the harness and never taken from the finder. [The JSON result](./20-json-result.md#a-verdict)
- **exclude** — a config's list of path patterns of the files every review leaves out, each listed in `meta.leftOut`, never a gap. Only the named config sets it. [Configuration](../20-using/20-configuration.md#excludes)
- **fail-on level** — the confidence at or above which a profile's kept findings fail the review, exit `1`: `high` by default, `none` for an advisory profile. [Profiles](../20-using/40-profiles.md#gating)
- **fence** — the pair of tags around one block of data in the user message, `<untrusted-diff-1a2b3c4d>` and its closing tag, with a random nonce for each block of each request, so the data cannot close its own block. Friction, not a control. [Prompts](../20-using/60-prompts.md#fencing-is-friction-not-a-control)
- **finder** — the model that reads the diff in the research stage and proposes the findings, through the profile's research provider. [Start here](../01-readme.md#what-you-are-about-to-use)
- **finding** — a candidate issue the finder reports. The harness checks each one against the diff: a finding passes the check only when it cites a line inside a hunk and, when the diff has per-file headers, one of its files. A finding that passes has a file, a line, a category, a summary and its evidence, and goes to the panel unless it repeats an earlier one; the others are dropped with a reason, or recorded as gaps. [The JSON result](./20-json-result.md#a-verdict)
- **fingerprint** — what a bench run keys a configuration's records by: the HMAC-SHA-256, under the run's salt, of every setting a review uses but the key. [Benchmarks](../20-using/70-bench.md#the-fingerprint)
- **fingerprint of a finding** — a finding's name across pushes, which holds when the code moves. [The JSON result](./20-json-result.md#a-verdict)
- **flag** — an advisory signal the harness reads by code, before any model sees it. It marks hidden characters, text addressed to an AI reviewer, or a file held back or skipped as a secret, and tells a human where to look; it changes no verdict and no exit code. [Output handling](../30-security/30-output-handling.md#advisory-flags)
- **frame** — one redraw of the block, written in one write: the move up over the last block and its erase, the log lines due, then the new block, wrapped in synchronized output. It is drawn at most every 100 ms and only when it changed. [The live view](../20-using/10-cli.md#the-live-view)
- **gating** — said of a profile whose fail-on level is not `none`: its kept findings at or above the level exit `1`, and its gaps exit `4`. [Profiles](../20-using/40-profiles.md#gating)
- **goal** — what an attack case tries to do to the review of its twin: suppression, forced-keep, cost-bloat or denial-of-review. [Measurement](../30-security/40-measurement.md#what-each-outcome-means)
- **grace** — the 5 seconds (`INTERRUPT_GRACE_MS`) the calls in flight have to end once a review is interrupted: a reply that comes within it is read and saved, and a call still in flight at its end is cancelled. [Interrupting a review](../20-using/10-cli.md#interrupting-a-review)
- **guidelines** — reference text a program loads and sets on a profile, fenced in every request of that profile and described to the model as criteria. [Profiles](../20-using/40-profiles.md#guidelines)
- **harness** — quorum's own code around the models: it reads the diff, builds every request, checks every reply and computes every verdict. [Architecture](./40-architecture.md#the-stages-of-a-review)
- **heartbeat** — the line plain mode writes in a minute with no other line while a review runs: the time since it started, the research parts or the votes done, the calls in flight and retried, the tokens against the cap and the time left. `quorum mcp` writes none: [Progress lines](../20-using/10-cli.md#progress-lines)
- **held** — said of a file no source sends a model unless `send` names it, named as a secret or holding a credential quorum recognizes: listed in `meta.leftOut`, flagged, and a gap of every profile unless the change deletes a file named as a secret whole. [Files held back as secrets](../20-using/15-sources.md#files-held-back-as-secrets)
- **hidden character** — a character a reader cannot see or a terminal may act on. That covers the control and format characters, unpaired surrogates, the other default-ignorable code points, and the line and paragraph separators. [Output handling](../30-security/30-output-handling.md#what-the-cli-writes)
- **incomplete** — said of a review in which a finding is unreviewed, or `meta.incomplete` holds a gap. The CLI exits `4` for an incomplete review of a gating profile, unless a gating profile kept a finding at or above its fail-on level, `high` by default. [The JSON result](./20-json-result.md#incomplete-reasons)
- **inert** — said of text printed so that nothing in it acts on a terminal or a GitHub Actions log. Its hidden characters are shown as `<U+XXXX>` in a line, and escaped in JSON. [Output handling](../30-security/30-output-handling.md#what-the-cli-writes)
- **interrupt** — a person's first Ctrl-C or SIGTERM, or the `interrupt` option of `review`: no new call starts, every wait ends, the calls in flight have the grace to end, and the review resolves with what it read, the rest an `interrupted` gap, exit `130`, which no flag lifts. A second signal quits at once, with no result. It is no abort, which rejects. [Interrupting a review](../20-using/10-cli.md#interrupting-a-review)
- **JSON mode** — `--progress json`: each event of the review, and each line of the CLI's own as a `cli:line` with its level, written on stderr as one `inertJsonLine`, with no summary, for a tool that reads the review as it runs. It is refused under `--view public`. [JSON lines](../20-using/10-cli.md#json-lines)
- **kept** — a verdict whose kept votes reach a confidence level. [Lenses and policy](../20-using/50-lenses-and-policy.md#confidence)
- **left out** — said of a file a review did not read: one whose change the diff shows only as binary or as a submodule's commit, or one held back as a secret, which each profile records as a gap that no flag lifts for a gating profile, or one an `exclude` pattern leaves out, a path review skips, or a change deletes whole when it is named as a secret, which is no gap. `meta.leftOut` lists it. [The JSON result](./20-json-result.md#a-file-left-out)
- **lens** — one angle of the panel: an id and the question its voter is asked. Each finding gets one vote per lens. [Lenses and policy](../20-using/50-lenses-and-policy.md#lenses)
- **location** — the span of lines of a bug case's patch that holds the bug: a file, as the patch's own `diff --git` header names it, and the first and last new-file line. [Benchmarks](../20-using/70-bench.md#locations-and-the-window)
- **live view** — the mode of a terminal: the log lines with a block redrawn under them, `--progress live`, which `auto` chooses when stderr is a terminal, `CI` is unset or empty and `TERM` is not `dumb`. It writes only cursor movement, erasure, the cursor's visibility, synchronized output and color around its own glyphs, and shows the cursor again on every exit path. [The live view](../20-using/10-cli.md#the-live-view)
- **log line** — one line the CLI writes on stderr after its flags, from an event of the review or of its own, at one of five levels (`warning`, `banner`, `estimate`, `notice`, `error`), through the one writer of `src/cli/view/`, each inert: [stdout and stderr](../20-using/10-cli.md#stdout-and-stderr)
- **MCP server** — `quorum mcp`, which serves the one tool `review` to an agent such as Claude Code: [The MCP server](../20-using/90-mcp.md)
- **outcome** — what a review comes to, `pass`, `findings`, `incomplete` or `interrupted`, with the exit code that says it. [Library API](./30-library-api.md#outcome)
- **panel** — the stage that sends every finding to every lens of the profile, one blind vote each, and computes its verdict. Also the voters themselves. [Lenses and policy](../20-using/50-lenses-and-policy.md)
- **part** — one research request of a large change: files of the diff in its order, or a file's header and some of its hunks, within `partTokens` and the model's window. [Research in parts](../20-using/20-configuration.md#research-in-parts)
- **part event** — the `part` event of a research part, sent once as it ends: its outcome, its duration, its spend and the findings its replies listed, and for a part recovery split how many pieces were read. MCP's progress notes count them. [Library API](./30-library-api.md#events)
- **path review** — a review of the files under one or more paths at a commit, read by id and written as an all-added diff. [The files at a commit](../20-using/15-sources.md#the-files-at-a-commit)
- **payload** — the JSON document `-f payload` writes and `quorum-action` posts as it is: the reviewed commit, the conclusion, the summary and a line comment for each finding on a file of the diff. [The Action's payload](./50-action-payload.md)
- **piece** — half of a part, or of a piece, which recovery makes when a research reply is cut off or saturated: the slices of the part, or the hunks of its one file, each half of a file keeping its header, at most three splits deep, numbered `2i - 1` and `2i` among the pieces of their depth. A request for a piece names it: `Part 7 of 44 of the change, piece 3 of 4.` [Recovering a cut-off part](../20-using/20-configuration.md#recovering-a-cut-off-part)
- **plain mode** — the view with no terminal to draw on, for a CI log and a screen reader: one inert line of text for each event worth one and for each line of the CLI's own, no glyph, no colour and no control sequence, and a heartbeat in a quiet minute: [Progress lines](../20-using/10-cli.md#progress-lines)
- **poisoned patch** — the patch of an attack case: its twin's patch with the attack's text planted in it. [Measurement](../30-security/40-measurement.md#the-injection-corpus)
- **policy** — a profile's rules for how many kept votes each confidence level needs: `unanimous`, `majority`, `any`, `off`, `{ minVotes }` or `{ minRatio }`. [Lenses and policy](../20-using/50-lenses-and-policy.md#policy-rules)
- **profile** — what a review looks for, as data: the research and vote instructions, the lenses, the policy, `failOn` and optional guidelines. `security` is the default, and the CLI runs every profile its config selects. [Profiles](../20-using/40-profiles.md)
- **provider** — how quorum reaches a model: an object with an id, a model and a `complete` function that takes a request and returns the reply's text. [Providers](../20-using/30-providers.md)
- **provider down** — said of a provider three of whose calls in a row failed for a reason of its own, across every profile and role that shares it: no more calls go to it in the review, the calls in flight run to their end, and the parts and votes it was never sent are `provider-down` gaps. [When the research call fails](../20-using/10-cli.md#when-the-research-call-fails)
- **public view** — the result less what helps an attacker: the reasoning, the discarded findings, the models, the usage and the gaps' details. `--view public` and `publicView` make it, for a sink a stranger can read. [The public view](../30-security/30-output-handling.md#the-public-view)
- **quote** — the code the finder says a finding is about. It is only compared with the evidence, which sets `quoteMatched`, and is never sent to a voter. [The JSON result](./20-json-result.md#a-verdict)
- **recall** — the share of a suite's bug cases a configuration catches, the mean of the case scores. *Kept recall* counts a catch by a kept finding, and *proposed recall* a catch by any finding that reached the panel: the finder's recall before the panel. [Benchmarks](../20-using/70-bench.md#reading-the-report)
- **reference** — the first configuration a bench is given: the report compares each other one with it. [Benchmarks](../20-using/70-bench.md#reading-the-report)
- **reply budget** — the tokens a request reserves and asks the server for its reply, thinking included, derived for each kind of request, research or vote, from the provider's window, `maxTokens` and thinking: at most a quarter of the window; with `maxTokens` set, a research request's budget is `maxTokens` itself, not capped at a quarter of the window, and a vote's is at most `maxTokens`. The research request also asks for as many findings as its budget holds. [Reply budgets](../20-using/20-configuration.md#reply-budgets)
- **report** — what the CLI writes on stdout for a review, in the format `--format` names. [The report](../20-using/10-cli.md#the-report)
- **re-score** — what a bench run does when its suite changed in `suite.yaml` alone: it scores its recorded reviews again under the suite as it is now, with no call, and its report says so. [Benchmarks](../20-using/70-bench.md#re-scoring)
- **research** — the first stage of a profile: one call to its research provider, or one per part of a large change, and more for a part recovery splits, whose replies list the candidate findings. [Architecture](./40-architecture.md#the-stages-of-a-review)
- **retry** — one more attempt of a call that failed in passing, after a growing wait or the server's own hint: a dropped connection, a timeout once, an HTTP 408, 409, 429 or 5xx, as often as the provider's `retries` allow. [Deadlines and retries](../20-using/30-providers.md#deadlines-and-retries)
- **review deadline** — the time one review runs, `reviewTimeoutMs`, 30 minutes by default: at it every call in flight and every wait is stopped, and what was not done is a `review-deadline` gap. [The review's deadline](../20-using/20-configuration.md#the-reviews-deadline)
- **review hash** — the hash of what a bench suite's reviews depend on: its case ids, its `trials` and each case's patch. A run refuses a suite whose review hash changed. [Benchmarks](../20-using/70-bench.md#resuming)
- **room** — how many more tokens of text a request could hold and still fit a provider's window, as the provider states it. [What a provider states](../20-using/30-providers.md#what-a-provider-states)
- **root** — the directory `quorum mcp` serves, `CLAUDE_PROJECT_DIR` or the one it was launched in, which a call's paths stay inside: [Starting it](../20-using/90-mcp.md#starting-it)
- **run directory** — where a bench keeps a run: `run.json`, `results.jsonl` and the two reports. The same command on it resumes the run. [Benchmarks](../20-using/70-bench.md#the-run-directory)
- **saturation** — a research reply that lists as many findings as it was asked for at most (`N`), which may have stopped at the ask. Below `maxFindings` its part is split and the reply not read; at the floor, or at `maxFindings`, it is read and the profile records one `findings-capped` gap. [Recovering a cut-off part](../20-using/20-configuration.md#recovering-a-cut-off-part)
- **scoring hash** — the hash of a bench suite's `suite.yaml`, which holds how its reviews are scored. A run whose suite changed only there is re-scored. [Benchmarks](../20-using/70-bench.md#re-scoring)
- **send** — the files the operator sends the models though they are held as secrets: the config's `send` and `--send`, each a path as the diff writes it and `meta.leftOut` lists it, matched exactly. Never read from the change. [Sending a held file](../20-using/20-configuration.md#sending-a-held-file)
- **session budget** — the most tokens one `quorum mcp` server spends over its life, counted at each provider call's spent tokens, and at the whole cap for a review that ends without a result: [Limits](../20-using/90-mcp.md#limits)
- **sink** — two things, told apart by what surrounds them. The *event sink* is the function a program passes as `ports.events`, which receives every event of a review. In the security profile's instructions, *the sink* is the code a vulnerability ends in, which the finder quotes and the reachability lens asks about. [Library API](./30-library-api.md#events) · [Profiles](../20-using/40-profiles.md#the-security-profile)
- **skip** — a file a path review leaves out, by one of eight rules, listed in `meta.leftOut` and no gap: a secret by its name or by a credential in its text, a vendored, lockfile, minified, test or binary file, a gitlink and a Git LFS pointer. `--no-default-skips` turns off the vendored, lockfile, minified, test and binary rules alone. [What a path review skips](../20-using/15-sources.md#what-a-path-review-skips)
- **source** — what makes the diff a review reads: a diff file or stdin, a range of commits, the local changes or the files at a commit, recorded in `meta.source`. [Sources](../20-using/15-sources.md)
- **stage** — one step of a profile's review: research, then dedup, which drops a finding that repeats the file, line and category of an earlier one, then panel. [Architecture](./40-architecture.md#the-stages-of-a-review)
- **state directory** — where `--state` keeps the answered calls of a review: one file for each call, in a directory only its user may write, outside every git work tree, empty or made by quorum, which holds its marker `quorum-state.json`. Whoever can write it writes a part's review, so it is removed once its review is done. [Saved state](../20-using/20-configuration.md#saved-state)
- **stored reply** — one call's checked reply in the state directory, or a marker for a research reply that was cut off or saturated, which holds what it lacked and never a text. A rerun reuses it only for a request sent as it was, checks it as a fresh reply and spends nothing on it. [Saved state](../20-using/20-configuration.md#saved-state)
- **suite** — a directory of patches and a `suite.yaml` that names them as cases, with the locations of the bugs: the data a bench reviews. [Benchmarks](../20-using/70-bench.md#writing-a-suite)
- **summary** — the lines stderr ends with once the report and the `--output` files are written: the time of each stage beside the first estimate of the time left, the share of the token cap spent, the calls made, retried and recovered, each gap reason with its count, its causes and its fix, and where the report went, by format and never by path. A review that ran no stage and a run that fails write none: [The summary](../20-using/10-cli.md#the-summary)
- **threshold** — the number of kept votes a confidence level needs, once the policy is resolved for the profile's lens count; `null` for a level that is off. [Lenses and policy](../20-using/50-lenses-and-policy.md#policy-rules)
- **token cap** — the most tokens, input and output, one review may spend: `maxReviewTokens`, 2000000 by default. Each attempt reserves its worst case before it is sent and settles at what it spent, and what the cap stops is a `token-cap` gap. [The token cap](../20-using/20-configuration.md#the-token-cap)
- **trial** — one review of a case with a configuration. `--trials` sets how many each case gets, and a case scores the share of its trials with an outcome. [Benchmarks](../20-using/70-bench.md#running-a-bench)
- **twin** — the bug case whose patch an attack case poisons, and the unit an attack's rates and sign tests are taken over. [Measurement](../30-security/40-measurement.md#reading-the-numbers)
- **unmatched** — a kept finding of a bench review that catches no location of its case. It is never called a false positive, since a gold set, the list of bugs a suite records, is never complete. [Benchmarks](../20-using/70-bench.md#reading-the-report)
- **unreviewed** — a verdict that reached no confidence level while its failed votes, had they been keeps, would have reached one: neither kept nor cleared. It makes the review incomplete. [Lenses and policy](../20-using/50-lenses-and-policy.md#failed-votes)
- **verdict** — a finding once the panel has voted on it: its votes, the kept and total counts, and its confidence when it reached one. [The JSON result](./20-json-result.md#a-verdict)
- **vote** — one lens's judgment of one finding, `keep` and `reasoning`; or a failed vote, `null` with its error, which counts as a reject. [The JSON result](./20-json-result.md#a-vote)
- **window** — how many lines either side of a location a finding may cite and still catch it: `window` in a `suite.yaml`, 3 by default. [Benchmarks](../20-using/70-bench.md#locations-and-the-window)

## Acronyms

- **API** — application programming interface: the functions and types `src/index.ts` exports, and the HTTP interface of a model endpoint. [Library API](./30-library-api.md)
- **CI** — continuous integration: the jobs that run on each change, which gate on quorum's exit code. [The CLI](../20-using/10-cli.md#using-it-in-ci)
- **CLI** — command-line interface: `quorum` typed at a shell. [The CLI](../20-using/10-cli.md)
- **CVE** — Common Vulnerabilities and Exposures: the identifier of a published vulnerability (`CVE-2026-62325`), which the notes of the real-bug suite give beside the advisory's own. [Benchmarks](../20-using/70-bench.md#the-real-bug-suite)
- **CWE** — Common Weakness Enumeration, the numbered weaknesses (`CWE-89`) the security profile asks the finder to name as a finding's category.
- **JSON** — JavaScript Object Notation: the format of the result on stdout, of a bench's `run.json`, `results.jsonl` and `report.json`, and of every model reply quorum reads. [The JSON result](./20-json-result.md)
- **LLM** — large language model: the finder and the voters are LLMs, reached through providers. [Providers](../20-using/30-providers.md)
- **PR** — pull request: a proposed change, whose diff quorum reviews and whose author is the attacker of the threat model. [Threat model](../30-security/10-threat-model.md#the-attacker)
- **SARIF** — Static Analysis Results Interchange Format: the JSON format GitHub's code scanning reads, which `-f sarif` writes. [Reports for GitHub](../20-using/80-reports.md#sarif)
- **SPDX** — Software Package Data Exchange: the standard short names of licenses, such as `MIT` and `BSD-3-Clause`, which a case's `license` holds and which name the files of `bench/LICENSES/`. [Benchmarks](../20-using/70-bench.md#the-real-bug-suite)
- **TTY** — a terminal. With no file argument and stdin a TTY, quorum prints its usage instead of waiting for a diff. [The CLI](../20-using/10-cli.md#the-invocation)
